# DevOps Repository Auditing Agent

A Python agent for auditing public GitHub repositories for evidence-based DevOps and software-engineering issues. The assignment specification is in [Assignment_2_DevOps_Repository_Auditing_Agent_Updated.pdf](./Assignment_2_DevOps_Repository_Auditing_Agent_Updated.pdf).

## Current status

The initial Python implementation is pushed to [the public GitHub repository](https://github.com/Abdullah009-nexus/devops-repo-auditing). The local working version adds a model-selectable audit tool with three conservative checks, exact evidence validation for those rule IDs, and synthetic healthy/defective fixtures. A live end-to-end LLM audit and authentic sample report have not yet been verified.

See [PROJECT_DOCUMENT.md](./PROJECT_DOCUMENT.md) for the current project summary and visual inspection guide, [PLAN.md](./PLAN.md) for phase-by-phase progress, and [MEMORY.md](./MEMORY.md) plus [DESIGN.md](./DESIGN.md) for implementation handoff and architecture. The Markdown handoff documents and assignment PDF are local; they were not included in the earlier source-only push.

## Requirements

- Python and a public GitHub repository URL.
- An OpenAI-compatible model endpoint configured through environment variables:
  - `OPENAI_API_KEY`
  - `OPENAI_MODEL`
  - Optional `OPENAI_BASE_URL` (defaults to `https://api.openai.com/v1`).
- No agent framework is used. Assignment constraints prohibit n8n, LangChain, LangGraph, and other prebuilt orchestration frameworks; the observe/reason/tool loop is implemented in Python.

## Run

```powershell
$env:OPENAI_API_KEY = "your-provider-key"
$env:OPENAI_MODEL = "your-model"
python agent.py --repo https://github.com/owner/repository --output report.json
```

The CLI writes a JSON report after a successful inspection and exits nonzero with an error message on fatal failures. Do not put real credentials in source files, reports, or commits.

## Inspection and safety

The required tool surface is implemented in [tools.py](./tools.py): list repository files, read a file, literal-search repository text, and inspect recent commits. An additional model-selectable tool audits files already read for a narrow set of security/CI patterns, implemented in [audit.py](./audit.py). The agent reads public GitHub content only; it does not execute repository code, install target dependencies, or modify the target. Limits and likely-secret redaction reduce risk but cannot guarantee detection of every secret pattern.

## Tests

Run the current tests with:

```powershell
python -m unittest discover -s tests -v
```

The current 33-test suite validates core utilities, GitHub API/network failure handling, strict tool arguments, provider failures, loop limits, report writing, CLI failure handling, a mocked multi-step tool-call flow, and three rules against small healthy/defective fixtures. Those fixture-only results are not a general accuracy estimate. Broader audit coverage, evaluation, and an end-to-end credential-configured run remain planned.

## Output

The report has a `repository` value and a `violations` array. Each violation must have `rule_id`, `category`, `severity`, `file`, `line`, `description`, `evidence`, and `recommendation`. Supported severities are `critical`, `high`, `medium`, and `low`. Inapplicable file/line values use JSON `null`; a clean run should produce an empty array.
